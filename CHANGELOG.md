## [Unreleased]

### Added

- Инструкция по деплою на Vercel и по переменным окружения в `Notes.md`.
- Полное описание проекта, локальный запуск и команды в `README.md`.
- Вход в приложение по паролю `APP_PASSWORD`: сессия в HttpOnly-cookie с подписью HMAC,
  экран `/api/auth` и блокировка при истечении. Без `APP_PASSWORD` прокси закрыт целиком.
- Отдельный пароль на изменяющие методы (`WRITE_PASSWORD`, по умолчанию `APP_PASSWORD`) и режим
  только для чтения через `APP_ALLOW_WRITES=false`. Мутации вне гранта получают `403`.
- **Голосовые сообщения теперь записываются в формате OGG/Opus (родной для Telegram),
  с фоллбеками WebM/Opus, WebM, MP4. Исправлена очистка состояния после отправки/отмены:
  UI возвращается в исходное состояние.**

### Changed

- Логотип и иконка вкладки: два диалоговых пузыря из набора Lucide вместо буквы «C»,
  нейтральный синий градиент, тот же знак в интерфейсе и в `favicon.svg`.
- Интерфейс не выглядит сломанным, когда API недоступен: область чата показывает состояние
  с кнопкой «Повторить», в сайдбаре появляется строка с ошибкой, чаты и профиль на месте.
- **Отредактированные локально имена контактов (firstName/lastName) теперь отображаются
  в шапке чата и в сайдбаре вместо имён из списка чатов.**
- **Переключатели уведомлений по чатам скрыты (комментированы в коде с пометкой TODO),
  так как GREEN-API не поддерживает per-chat notification state. Сохранена логика
  для будущего включения.**
- Версия pnpm зафиксирована в `package.json`, поэтому сборка обращается к нужной версии
  пакетного менеджера, а не к самой свежей в реестре.
- Dev-сервер запускает те же обработчики `api/`, что и serverless-функции, вместо прямого
  проксирования `fetch` на GREEN-API: локальная разработка проверяет гейт и лимиты так же,
  как прод.
- `server.js` обслуживает `/api/auth`, `build:server` собирает `api/auth.ts`.

### Fixed

- `pnpm run docker:build` собирает образ: в локальной сети DNS из docker-сети недоступен,
  поэтому сборка идёт через host networking и установка зависимостей проходит.
- `pnpm run docker:run` тоже переведён на host networking: из-за того же DNS контейнер получал
  `502 Bad Gateway` на `/api/greenapi/*`, потому что GREEN-API был недоступен из docker-сети.
  Порт публикуется напрямую, проброс `-p` больше не используется.

### Security

- Прокси GREEN-API больше не открыт: без сессии приложения не проходит ни один метод, поэтому
  запрос из `curl` без cookie получает `401`, а не список чатов. `/api/og` тоже закрыт сессией,
  иначе сервер работал бы как открытый fetcher для любого, кто знает его адрес.
- Проверка origin пропускала запросы без заголовка `Origin`; закрытый контур держит сессия,
  а ошибка гейта отличается заголовком `WWW-Authenticate`, поэтому 401 инстанса и 401 сессии
  различаются на клиенте.
- Изменяющие методы (`sendMessage`, `deleteMessage`, `forwardMessages`, `logout`, контакты,
  группы, архив, загрузка файлов) вынесены из allow-list чтения и требуют подтверждения паролем;
  allow-list задан на сервере, всё новое по умолчанию считается мутацией.
- На вход в приложение стоит счётчик неудачных попыток: пять попыток с одного адреса дают
  блокировку на пять минут.
- Тесты на подпись и проверку cookie, на эндпоинт входа с блокировкой перебора, на гейт прокси
  и на allow-list методов.

## [0.1.0] - 2026-10-03

### Added

- Вход в Telegram через QR-код, код из приложения и 2FA-пароль с ожиданием авторизации.
- Прокси GREEN-API на сервере: токен инстанса не попадает в бандл браузера.
- Список чатов с превью последнего сообщения, временем и счётчиком непрочитанных, который
  считается по загруженной истории (с пометкой «10+», если окно закончилось).
- Лента сообщений: текст, ответы на сообщения, пересылка, удаление, показ удалённых,
  статусы отправки и отметки о прочтении.
- Медиа: фото, видео, документы и аудио — отправка, ленивая загрузка, полноэкранный просмотр,
  скачивание, восстановление превью, которые Telegram отдаёт без расширения.
- Голосовые сообщения: запись с живой визуализацией, пауза, воспроизведение, удаление записи.
- Постраничная догрузка истории вверх по IntersectionObserver с сохранением позиции чтения.
- Поиск по сообщениям внутри чата и по чатам в списке.
- Панель информации о пользователе и группе: имя, телефон, ник, «был(а) недавно», медиа,
  ссылки, участники группы, локальный профиль контакта.
- Превью ссылок: серверный разбор OpenGraph с картинкой и названием сайта.
- Локальные настройки: mute чатов, показ удалённых сообщений, сохранение открытого чата.
- Кеш прочитанных сообщений в IndexedDB: открытый чат рисуется до ответа сети.
- ErrorBoundary вокруг области чата.
- Docker-образ и `docker compose` для self-hosting.
- Деплой на Vercel: функции из `api/`, SPA-fallback и заголовки безопасности.

### Changed

- Список чатов и история открытого чата грузятся параллельно, поэтому медленный ответ истории
  больше не блокирует весь экран.
- Интерфейс отрисован иконками react-icons, сетка приведена к пропорциям Telegram.
- Крупные хуки и виджеты разбиты на узкие модули: список чатов, выбор чата, кеш истории,
  догрузка страниц, поиск в шапке, меню шапки, карточка контакта.
- Формирование дат и времени перенесено на переиспользуемые `Intl.DateTimeFormat`
  с мемоизацией результатов.
- Дескрипторы медиа считаются один раз на сообщение и передаются компоненту стабильной ссылкой.
- Компоненты списков и ленты мемоизированы (`React.memo`), производные данные — через `useMemo`.

### Fixed

- Пагинация истории больше не запрашивает страницы, которых никто не ждёт: цикл останавливается,
  как только верх списка уходит из поля зрения.
- Счётчик непрочитанных не сбрасывается при каждом открытии списка.
- Аватары и карточки контакта не расходуют месячную квоту: ответы кешируются, а при ошибке 466
  метод приостанавливается, а не повторяется.
- Панель информации сообщает, когда имя, телефон и ник взяты из списка чатов, потому что
  `getContactInfo` не ответил.
- Восстановлено отображение аватаров и загрузка списка чатов.
- Возврат на экран входа при ответе 401 от GREEN-API.

### Security

- Прокси отклоняет кросс-доменные вызовы, ограничивает тело запроса 1 МБ и ответ 8 МБ и не
  пересылает `set-cookie` и CORS-заголовки апстрима.
- `/api/og` проверяет каждый хоп редиректов и блокирует loopback, link-local, приватные, ULA,
  CGNAT и multicast-адреса; кеш превью ограничен 500 записями.
- Статика отдаётся с CSP, `X-Content-Type-Options`, `X-Frame-Options` и `Referrer-Policy`.
- Путь к файлу статики нормализуется и проверяется на выход за пределы `dist`.
- Тесты на прокси и на превью ссылок: allow-list методов, заголовки, лимиты, origin, редиректы.

### Removed

- Поле «день рождения» из карточки контакта: GREEN-API его не отдаёт.
